# 🔁 حلقة التدريب: وصفة ← تدريب ← إعادة اختبار ← تقييم ← تكيّف

> **الهدف:** أن تكون كل خطة تدريب **تجربة صغيرة على اللاعب نفسه**، لها فرضية ("تمرين X سيحسّن مهارة Y")، ومدة، وقياس قبل وبعد، وحكم إحصائي صادق.

---

## 1. دورة الحياة

```
          ┌──────────────────────────────────────────────────────┐
          ▼                                                      │
  [Baseline Assessment] ──▶ [Diagnosis] ──▶ [Plan: Block N]      │
                                              │                  │
                         ┌────────────────────┘                  │
                         ▼                                       │
         ┌── Day 1..K: Daily Session (12–20 min) ──┐             │
         │  warm-up → focus drill A → focus drill B│             │
         │  → maintenance → mini-check (60s)       │             │
         └───────────────────┬─────────────────────┘             │
                             ▼                                   │
                [Retest: full battery, new form]                 │
                             ▼                                   │
                [Evaluation: MDC + DiD + retention]              │
                             ▼                                   │
                [Adapt: continue / switch drill / new focus] ────┘
```

### حالات الخطة (State Machine)
```rust
pub enum PlanState {
    Draft,                                   // اقتُرحت ولم يقبلها اللاعب
    Active { block: u8, day: u8 },
    AwaitingRetest { due: Date },
    Evaluated { outcome: BlockOutcome },
    Paused { reason: PauseReason },          // غياب > 4 أيام ← نعيد baseline قصيراً عند العودة
    Completed,
}
```

## 2. الوصفة (Prescription)

### 2.1 قوالب التمارين (Drill Templates)
كل تمرين ملف بيانات، وله **معامل صعوبة واحد `d ∈ [0,1]`** يتحكّم بعدة متغيرات معاً:

```ron
// content/drills/deceleration_ladder.ron
Drill(
  id: "deceleration_ladder",
  targets_skills: [S04_GAIN_CONTROL, S05_MICRO_CORRECTION],
  for_findings: ["D2", "D4"],
  description_key: "drill.decel_ladder",
  duration_s: 120,
  difficulty: Curve(
    // d=0 → سهل، d=1 → صعب
    target_radius_deg: Lerp(1.2, 0.45),
    flick_distance_deg: Lerp((10, 20), (25, 50)),
    time_limit_ms: Lerp(1800, 700),
    // "Stop short" mechanic: overshooting beyond 1.1×D = fail
    overshoot_fail_ratio: Lerp(1.25, 1.08),
  ),
  success: Hit(within_time: true, no_overshoot_fail: true),
  feedback: Live(show_gain_bar: true),   // يرى اللاعب G لكل فليك فوراً
)
```

**مبدأ التصميم:** كل تمرين يجب أن يعطي **تغذية راجعة فورية على نفس المقياس** الذي يقيسه التشخيص. مثلاً تمرين overshoot يُظهر "شريط G" بعد كل فليك، فيتعلّم اللاعب الإحساس الصحيح بسرعة.

### 2.3 بناء الجلسة اليومية
```
Daily Session (Pro, ~16 min):
  1. Warm-up            2 min   (large targets, لا يُقاس)
  2. Focus drill A      5 min   (أعلى أولوية، 2–3 فترات × 2 دقيقة مع راحة 20s)
  3. Focus drill B      4 min   (ثاني أولوية)
  4. Variation          2 min   (نسخة مختلفة من A — انظر 2.4)
  5. Maintenance        2 min   (أقوى مهارات اللاعب؛ لمنع التراجع والحفاظ على الحافز)
  6. Mini-check         1 min   (اختبار ثابت قصير للمهارة المستهدفة؛ لرسم منحنى يومي)
```

### 2.4 التنويع (Variability) بجرعة محسوبة
الأدبيات في التعلّم الحركي لا تدعم أن "التنويع أكثر = أفضل" بشكل مطلق؛ فأثره يعتمد على مستوى المتعلّم ومقداره. لذلك:
- **الأيام 1–2:** ممارسة ثابتة (constant) لنفس الإعدادات، لتثبيت الإحساس.
- **الأيام 3+:** تنويع متزايد (مسافات/أحجام/سرعات مختلفة حول نفس المهارة).
- **مُعامل قابل للتعلّم:** نسبة التنويع تُضبط لاحقاً بالـ bandit (القسم 6).

## 3. الصعوبة التكيفية (Staircase)

**الهدف:** إبقاء معدل النجاح قرب **~75%** (منطقة التحدي: ليست سهلة فتصبح مملة، وليست صعبة فتصبح محبطة).

```rust
/// Weighted up/down staircase (Kaernbach 1991) targeting p* success rate.
pub struct Staircase {
    pub d: f64,          // current difficulty 0..1
    step_up: f64,        // after success
    step_down: f64,      // after failure
}
impl Staircase {
    pub fn new(d0: f64, target_p: f64, step: f64) -> Self {
        // equilibrium: p*·up = (1−p*)·down  →  down = up · p*/(1−p*)
        Self { d: d0, step_up: step, step_down: step * target_p / (1.0 - target_p) }
    }
    pub fn update(&mut self, success: bool) {
        self.d = if success { self.d + self.step_up } else { self.d - self.step_down }
            .clamp(0.0, 1.0);
    }
}
// target_p = 0.75, step = 0.02  →  step_down = 0.06
```

- قيمة `d` النهائية لكل تمرين **تُحفظ**، فالجلسة التالية تبدأ من حيث انتهى اللاعب.
- **`d` نفسه مؤشر تقدّم:** منحنى `d` عبر الأيام يُعرض للاعب ("مستوى التمرين").
- لكن **تقييم التحسّن الرسمي لا يعتمد على `d`**، بل على إعادة الاختبار الموحّد (لأن `d` يتأثر بالتعوّد على التمرين نفسه).

## 4. مدة الكتلة وتوقيت إعادة الاختبار

| الإعداد | القيمة الافتراضية | المنطق |
|--------|------------------|--------|
| طول الكتلة | **6 أيام تدريب** (ضمن 7–9 أيام تقويمية) | وقت كافٍ لتغيّر قابل للقياس في المهارات السريعة التعلّم، وقصير بما يكفي للحفاظ على الحافز |
| الجلسة اليومية | 12–20 دقيقة | |
| إعادة الاختبار | **بعد يوم راحة واحد على الأقل** من آخر تدريب | نقيس التعلّم الثابت وليس أثر الإحماء اللحظي |
| اختبار الاحتفاظ (Retention) | تقييم مصغّر بعد **7+ أيام** من انتهاء التركيز على مهارة | هل بقي التحسّن؟ |
| التمديد | إذا لم يكتمل 4 من 6 أيام ← تُمدَّد الكتلة ولا تُقيَّم | تقييم كتلة ناقصة يعطي نتيجة مضلّلة |

## 5. التقييم الإحصائي (Evaluation) ⭐ قلب المصداقية

### 5.1 الضجيج: SEM و MDC
لكل مهارة ولكل اختبار في البطارية:
```
SEM   = SD_pooled × sqrt(1 − ICC)          // من تجربة test-retest في نفس اليوم (Beta)
MDC95 = 1.96 × sqrt(2) × SEM               // أصغر تغيّر يمكن تمييزه عن الضجيج بثقة 95%
```
- **يُحسب من الـ Beta:** 100+ لاعب يجرون البطارية مرتين بفاصل 30–60 دقيقة دون تدريب بينهما.
- **وعلى مستوى الفرد:** بعد 3+ تقييمات للاعب نفسه نستخدم تباينه الشخصي (أدقّ من تباين المجموعة)، مع shrinkage نحو قيمة المجموعة:
```
SEM_personal = sqrt( (k·SEM_pop² + n·s_player²) / (k + n) )     // k = 4 (prior weight)
```

### 5.2 حكم التغيّر لكل مهارة
```
Δ = score_post − score_pre

Δ ≥ +MDC              → ✅ تحسّن مؤكّد
+MDC/2 ≤ Δ < +MDC     → 🟡 تحسّن محتمل (يحتاج تأكيد في الاختبار التالي)
|Δ| < MDC/2           → ⚪ لا تغيير قابل للقياس
Δ ≤ −MDC              → 🔻 تراجع (نبحث عن السبب: تعب؟ تغيّر إعدادات؟)
```

### 5.3 فصل أثر التدريب عن أثر الاختبار: Difference-in-Differences ⭐
المشكلة: أي لاعب يتحسّن قليلاً في الاختبار الثاني لأنه تعوّد على البطارية واللعبة، حتى بلا تدريب.
الحل: نقارن **المهارات المُدرَّبة** بـ **المهارات غير المُدرَّبة** لنفس اللاعب:

```
Δ_trained   = mean(Δ for focus skills)
Δ_untrained = mean(Δ for skills not targeted this block, excluding maintenance)
Training Effect (DiD) = Δ_trained − Δ_untrained
```
ونعرض للاعب:
> "مهارة التحكم بالمدى تحسّنت **+14 نقطة**. مهاراتك الأخرى (التي لم تتدرّب عليها) تحسّنت **+3** فقط، أي أن **~11 نقطة على الأقل جاءت من التدريب نفسه**."

**هذه الميزة التي لا يقدّمها أي منافس.**

### 5.4 نموذج تتبّع المهارة عبر الزمن (Kalman 1D)
بدلاً من أخذ كل اختبار كحقيقة مستقلة، نتتبّع "المهارة الحقيقية" بفلتر:
```rust
pub struct SkillTrack { mean: f64, var: f64 }
impl SkillTrack {
    /// q: process noise per day (skill drift), r: measurement noise = SEM²
    pub fn predict(&mut self, days: f64, q: f64) { self.var += q * days; }
    pub fn update(&mut self, obs: f64, r: f64) {
        let k = self.var / (self.var + r);
        self.mean += k * (obs - self.mean);
        self.var *= 1.0 - k;
    }
}
```
- يعطي **منحنى تقدّم ناعم** مع نطاق ثقة، بدل قفزات مزعجة.
- يدمج الـ mini-checks اليومية (ضجيجها أعلى، فوزنها أقل) مع التقييمات الكاملة.

### 5.5 قرار التكيّف (Adapt)
```
بعد كل كتلة، لكل مهارة مركّز عليها:
  ✅ تحسّن مؤكّد، وscore ≥ الهدف (مثلاً percentile 60 لرتبته)
        → "تخرّجت": تنتقل للـ maintenance، وتدخل المهارة التالية في الأولوية
  ✅ تحسّن مؤكّد، ولم تصل للهدف
        → كتلة أخرى بنفس التمرين، و d يبدأ من آخر قيمة
  🟡 / ⚪ لا تغيير (للمرة الأولى)
        → نغيّر التمرين إلى بديل لنفس المشكلة (drill variant)
  ⚪ لا تغيير (للمرة الثانية)
        → نعيد التشخيص: هل السبب الجذري مختلف؟ (مثلاً D3 بدل D2) + اقتراح تجربة الحساسية (6.2 في وثيقة التشخيص)
  🔻 تراجع
        → فحص الظروف (إعدادات، frame stats، fatigue) + سؤال اللاعب + كتلة أخف
```

## 6. الذكاء المتعلّم (المرحلة 6 — بعد تراكم البيانات)

### 6.1 Contextual Bandit لاختيار التمرين
- **السياق (x):** ملف المهارات، الرتبة، cm/360، Hz، التشخيص الرئيسي، وتاريخ الاستجابة للتمارين.
- **الأفعال (a):** التمارين المرشحة لهذا التشخيص (3–5 لكل finding).
- **المكافأة (r):** `DiD` المعياري للمهارة المستهدفة بعد الكتلة (÷ MDC).
- **الخوارزمية:** Thompson Sampling مع نموذج خطي Bayesian (LinTS)؛ بسيط، وقابل للتفسير، ويعمل مع بيانات قليلة.
- **الأمان:** نبدأ بـ 80% exploitation من القواعد اليدوية و20% exploration، ونزيد الثقة بالنموذج تدريجياً.

### 6.2 تعلّم معاملات الخطة
بنفس الطريقة نتعلّم: طول الكتلة الأمثل، ونسبة التنويع، ومدة الجلسة لكل نوع لاعب.

### 6.3 Diagnoser متعلَّم
عندما يوجد 10k+ تقييم: نموذج (Gradient Boosting ← ONNX) يتنبأ بـ "أي finding سيستجيب للتدريب أكثر". يُستخدم **كترتيب للأولويات** بجانب القواعد، وليس بديلاً لها، حفاظاً على قابلية التفسير.

| يربط النتائج بمواقف VALORANT (peek، hold، retake) | |

```jsonc

{
  "locale": "ar",
  "player": {"rank": "Gold 2", "cm360": 46.6},
```

## 8. الواجهة: ما يراه اللاعب

1. **بطاقة التشخيص:** "مشكلتك الأولى: تتجاوز الهدف في الفليكات الطويلة (+13%)" ← زر "لماذا؟" يعرض رسماً لمسار 5 فليكات حقيقية من جلسته مع نقطة نهاية الحركة الأولى.
2. **الخطة:** تقويم 6 أيام، ويوم اليوم بارز، وزر "ابدأ جلسة اليوم (16 د)".
3. **منحنى المهارة:** Kalman mean + نطاق ثقة + علامات الكتل.
4. **شاشة نتيجة الكتلة:** الحكم (✅/🟡/⚪/🔻) + DiD + "ماذا بعد".
5. **بطاقة المشاركة:** "حسّنت التحكم بالمدى +14 خلال 6 أيام — مُثبت إحصائياً ✅".
